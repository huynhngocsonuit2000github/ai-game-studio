# Save, acceptance, and release

## Save contract

Use `ai-game-studio:monster-survivor:campaign:v1` with `schemaVersion: 1`, wallet, rank by known item ID, equipment by slot, stable cleared stage IDs, best time by cleared stage and a bounded settled-attempt ID list. Keep the existing `ai-game-studio:monster-survivor:v1` for shared settings, cosmetic and Normal records. Campaign records never modify Normal run totals. An old save sees stage 1 with beginner gear and still has its preferences, records and discovered skills. No automatic storage deletion. Corrupt Campaign data falls back with visible notice; a future version remains read-only without overwriting bytes. If storage is unavailable, show session-only status.

Stages unlock in cleared-order sequence. Stage 1 starts unlocked. Clear only on touching and confirming a reachable unlocked exit after objectives complete. Defeat and 07:00 safety timeout are terminal losses; keep collected gold and gear. Voluntary quit, active restart or browser close abandon unbanked rewards, with notice in the confirmation for quit/restart. Restart after results uses rewards already banked. Opening a chest or defeating a target generates world drops; only pickups actually collected will bank. First-clear equipment is added at successful exit, with a fixed duplicate gold reward if already owned. Keep pending rewards entirely inside the attempt. Terminal settlement writes wallet, new gear, first-clear bonus, completed stage, best time and attempt key as one snapshot before actions become available. Button presses/retries never double-pay. An upgrade transaction requires a valid owned item, expected previous rank and sufficient funds, updates the wallet and rank together and caps at +3. Permanent items only equip at camp. All item stats at rank `n` use values at array index `n`. Damage cap and state logic must be shared by UI and combat. Campaign rollback to the pinned Normal revision leaves the separate Campaign save available if the expansion is redeployed.
