# Technical design

Target the repository's existing strict TypeScript and static-build conventions. First check the trusted workspace toolchain. Use Canvas 2D and accessible DOM controls and HUD if the existing repository permits a game-local build with no new external package or root lockfile changes. Prefer the repository's existing 2D engine if already available under trusted scope, with equivalent acceptance. Take input from one command boundary. Keep simulation and content independent of the renderer. Read TUNING.json as authored seed data or generate an equivalent typed asset at build time. Static art, no network service, telemetry or API keys. Follow the repository's Pages entry, base path and catalog preflight. Use a relative portal return link.

## State and determinism

App states: title, campaign, briefing, prep, combat, paused, results, ending. Pause is a controlled transition retaining previous state; auto-pause on visibility loss and require explicit resume. Pause stops wave clock, cooldowns, hazard times, animation effects, and audio beds. Fixed 30 Hz simulation with bounded catch-up (up to five steps per display tick); discard stale elapsed time after focus/visibility loss. Time is simulation ticks. Convert authored seconds to ticks once for schedule and use epsilon-safe thresholds. Non-gameplay effects may interpolate independently. Queue inputs at step start. Update in a stable order: commands → timed hazards/spawns → enemy move/melee → plant actions and existing impacts → deaths, rewards, escapes and result arbitration. On simultaneous events, sort by source event ID, and remove dying entities at the end of the action phase with a dead flag so there is no duplicate damage/reward. A kill and escape in the same step is resolved as a kill if damage lands before removal and HP reached zero. Core 0 takes precedence over victory. Pacing scale, if used by browser tests, must be opt-in from dev/test harness only and absent from a production bundle's controls.

Collision: distance in lane tile units; nearest blocker ahead of enemy travel is the plant at greatest x between its previous/proposed positions including contact radius. Contact radius 0.42 tile from plant center. Clamp before crossing. Unlock next stage atomically when a qualifying result is recorded. Keys: `midnight-greenhouse.progress.v1`, `midnight-greenhouse.settings.v1`. Store only validated schema version, wins, best stars, fastest win because reload starts fresh; derive unlocked stages from contiguous wins. Use safe defaults for corrupt/unknown fields, in-memory fallback if storage is unavailable and a visible Vietnamese status for unsaved sessions. Avoid save reset on renderer restart.

## Runtime assets and layout

Load arena 01, six plant icons/sprites and necessary enemies on demand once. Defer remaining arenas and optional audio until menu/briefing as applicable. Asset failure must surface a clear bilingual-log/Vietnamese-player message and retry; implement null-audio fallback with sliders still functional. Use exact per-arena coordinate calibration in `design/ART_DIRECTION.md` and `assets/runtime/art/layout.json`. Keep simulation coordinates normalized across arenas; map visual rows separately. Draw feet at the per-lane baseline and spawn off right. DOM HUD uses responsive safe areas beyond board; support landscape 844×390 for touch and 1280×720 desktop. On portrait, show a functional rotate hint and keep settings/return accessible; preserve attempt while rotating. Scale board using one shared transform for both input and render. Show keyboard focus visually. Hit targets ≥44 CSS px where possible; four lane tabs and placement tiles must remain tappable at minimum supported landscape viewport without overlap. Use regular Vietnamese-capable system font stack and check diacritics.

## Budgets and evidence

Targets, not measured results: initial compressed transfer ≤5 MiB, complete runtime ≤15 MiB, no attachment concept images in production output. At 1280×720 current Chromium and Firefox on desktop with integrated graphics: median near 60 FPS, p95 frame ≤25 ms on a 30 s heavy segment on level 3. At 844×390 target Chrome Android mid-tier: median ≥30 FPS and p95 frame ≤45 ms; desktop emulator is separate evidence. Aim heap ≤120 MiB Chromium after 10 restarts and ≤4 s cold title on a 10 Mbps / 100 ms test profile; record tool and sampling details. Bound rain/particles/projectiles/shock effects and release collection entries; test twice through the final fight and inspect entity counts after restart. Safari smoke where available; achievable evidence records platform limits rather than assuming compatibility. Keep particles reduced under reduced motion; do not remove semantic telegraphs.

Capture per level: production subpath screenshot with an active wave and gameplay UI, console/network logs, seed/build identity and a reproducible normal-speed clear path. Complete three-level progression in one fresh browser profile, then reload and verify unlocked levels plus best records. Campaign must work via direct build URL and through temporary catalog preflight; verify unpublished content stays outside real catalog. Do not claim live deployment before actual distinct main artifact and URL check.
